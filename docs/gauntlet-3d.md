## Part 2 — The gauntlet prompt

```markdown
## Task
Expand the existing 2D Canvas murmuration simulation into 3D using Three.js,
to a standard where it reads as a real starling murmuration rather than as
particles in a box. Existing codebase at src/ — simulation, render, and ui are
already separated; preserve that separation.

## Build method
Fan out sub-agents, one per bar item below, except the MACHINE items which one
agent owns collectively. Each agent owns its remit and is a harsh critic of it —
it signs off only on work that clears its item, not work that approaches it.

Additionally spawn one wildcard agent whose remit is to find what this bar
missed. Its findings are reported at the end and are NOT fed back into the
loop.

Ultracode.

## The bar

1. [RIVAL] Screenshot the running simulation and place it beside the reference
   stills in examples/. Judge blind. The question is NOT "which is real" — a
   render and a photograph are always distinguishable and that framing makes
   the item unpassable. The question is: covering the labels, which image
   reads as a flock of birds and which reads as a scatter of objects? Pass
   requires the simulation to be chosen, or genuinely tied, on the majority of
   reference stills.

2. [MACHINE] Sustained 60fps at 2000 boids in 3D. Measure on the machine you
   are running on and record which machine that was in the report — the number
   is meaningless without it.

3. [MACHINE] No O(n²) neighbour search anywhere in the simulation loop. Verify
   by reading the source, not by timing. Spatial hash or octree; per-boid draw
   calls replaced with instancing.

4. [MACHINE] No NaN or Inf in any boid position or velocity after ten minutes
   of unattended running. Boids destabilise in unglamorous ways when an axis
   is added.

5. [HUNT] Sphericalisation. Cohesion across three axes pulls the flock into a
   featureless ball. Real murmurations are sheets, ribbons and columns and are
   never spheres. Go looking for this specifically — it is the single most
   likely way 3D boids fail, and if it happens nothing else on this list
   matters.

6. [HUNT] Volume without density. 2000 boids spread through a third axis can
   read sparser than 200 did in 2D. The reference stills show dark cores and
   visible density gradients, not an even scatter. Hunt for uniformity.

7. [HUNT] Camera. 2D had one implicit viewpoint for free; 3D has infinite and
   most are bad. From inside the flock, or directly overhead, a murmuration
   reads as nothing. This has no 2D equivalent, which is exactly why it will
   get neglected. Hunt for viewpoints that destroy the effect, and establish
   defaults that do not.

8. [HUNT] Shimmer. The light/dark flicker as birds present wing versus flank.
   It is a signature property visible in any reference still and it is
   unavailable to 2D triangles — 3D is the first time it CAN exist. Hunt for
   its absence.

## Stop rule
Each item is signed off individually and then locked; that agent stands down
and does not reopen it. MACHINE items (2, 3, 4) re-run every round regardless
of prior sign-off — they are cheap and there is no reason to accept regression
on them.

Stop when all items are signed off, or after 3 rounds — whichever comes first.
If the cap is hit, report which items are still open and why.

## Out of scope
Do not send work back for any of the following:

- The predator system. It works and its design was deliberate. Porting it to
  three axes is in scope; redesigning its behaviour is not.
- The UI. lil-gui is fine. Do not improve the control panel.
- Biological accuracy of individual flight — wingbeat, banking, per-bird
  kinematics. Murmurations read as texture at distance. This is the wrong axis
  and it is expensive.
- The framework. Three.js is chosen. Do not propose a WebGPU rewrite.
```
